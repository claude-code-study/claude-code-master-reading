# Data Model: Ticket Creation API

## Ticket

Represents a unit of work on the Tika board.

| Field | Type | Required | Creation Rule |
|-------|------|----------|---------------|
| id | number | response | Generated by persistence/service layer |
| title | string | request/response | Required, 1-200 chars, whitespace-only invalid |
| description | string \| null | response | Optional request field, max 1000 chars, defaults to null |
| status | `BACKLOG` | response | Always `BACKLOG` on creation |
| priority | `LOW` \| `MEDIUM` \| `HIGH` | response | Optional request field, defaults to `MEDIUM` |
| position | number | response | New Backlog top position |
| plannedStartDate | `YYYY-MM-DD` \| null | response | Optional request field, defaults to null |
| dueDate | `YYYY-MM-DD` \| null | response | Optional request field, defaults to null; past dates invalid |
| startedAt | ISO timestamp \| null | response | Always null on creation |
| completedAt | ISO timestamp \| null | response | Always null on creation |
| createdAt | ISO timestamp | response | Set on creation |
| updatedAt | ISO timestamp | response | Set on creation |

## CreateTicketInput

Request body accepted by `POST /api/tickets`.

| Field | Type | Rule |
|-------|------|------|
| title | string | Required, 1-200 chars after rejecting whitespace-only input |
| description | string | Optional, max 1000 chars |
| priority | string | Optional, one of LOW, MEDIUM, HIGH |
| plannedStartDate | string | Optional, `YYYY-MM-DD` |
| dueDate | string | Optional, `YYYY-MM-DD`, must be today or later in Asia/Seoul |

## ValidationError

Standard API error response for invalid create requests.

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "문서화된 검증 실패 메시지"
  }
}
```

## State Rules

- Creation never creates TODO, IN_PROGRESS, or DONE tickets.
- Creation never sets `startedAt` or `completedAt`.
- Creation does not compute `isOverdue`; that is a board/detail read concern.
- Validation failure must not mutate ticket data.
